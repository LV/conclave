# ADR 0003: Use Go for the CLI and run engine

**Status:** Accepted

## Context

[ADR 0001](0001-stateful-cli.md) puts a standalone CLI between the calling harness and the run engine. Installation should be simple: put `conclave` on `PATH`, directly or through a package manager such as Homebrew, and let a harness invoke it. The first release prioritizes concurrent fan-out, deadlines, partial results, and durable run records over broad provider support or deep integration with a particular harness SDK.

## Decision

Build the CLI and run engine in **Go**. Ship a standalone executable per supported platform so callers do not have to install or manage a separate language runtime. Go's goroutines, `context`, and `os/exec` give us a straightforward starting point for concurrent requests, cancellation, and subprocess integration. This is a distribution and implementation choice, not a performance requirement.

## Alternatives considered

- **TypeScript:** Offers broader model-provider tooling and direct access to Node-based harness SDKs. It can also ship as a standalone executable, but that requires an additional packaging step. A harness's language doesn't matter at the CLI boundary, so native SDK integration isn't a reason to build the core in TypeScript today.
- **Rust:** Offers similarly simple distribution and strong types for modeling workflow states. We chose Go for lower expected implementation friction in the first concurrent, I/O-bound workflow, not because Rust lacks the necessary capabilities.
- **Python:** Can implement the workflow well, but a conventional install needs an interpreter and dependencies. Bundling is possible; it adds packaging work that we prefer to avoid for the default install.

## Consequences

We get a straightforward path to standalone releases. We may need to write more provider adapter code than we would in TypeScript. Harness plugins can still be written in whatever language their host requires and call the same binary. The choice does not settle the CLI framework, database, provider libraries, or Homebrew release setup.
